# クロノ・デュエル（Chrono Duel）

ターンのない対戦カードゲーム。すべての行動は「時間（刻）」を支払い、**時計が遅れている方が次に行動する**。

- PixiJS 8 + TypeScript + Vite
- ブラウザで動作（スマホ縦画面／PC）、1戦およそ10〜15分
- AI対戦（ふつう／つよい）、デッキ編集、はじめての人向けガイド付き
- PWA対応：ホーム画面に追加して全画面で遊べ、オフラインでも起動します
- 第1弾パック「残響の刻」：新カード30種（追加カード8種を含む）。対戦で得たコインでパックを開封（ゲーム内通貨のみ、課金なし）
- オンライン対戦：あいことば／招待リンクで友達と対戦（サーバーが状態を持つ方式）

## ルール概要

| 項目 | 値 |
|---|---|
| 拠点の体力 | 15 |
| 時計の終わり | 40刻（両者が到達したら体力の多い方が勝ち） |
| 行動コスト | カード＝コスト分、攻撃1、ドロー2、待機1 |
| 鐘（1枚ドロー） | 8・16・24・32刻 |
| 終焉の刻 | 20刻から拠点へのダメージ+1、以降8刻ごとに+1 |
| 未来予約 | 術を未来の時刻に伏せる。同じコストで、発動時は効果が強化。各2枚まで |
| デッキ | 20枚、同名2枚まで（伝説は1枚） |

数値はすべて `src/core/rules.ts` にまとまっています。

## 画面構成

タイトル（TAP TO START、初回はプレイヤー名の入力）→ ホーム。ホームと各タブは下部のタブバーで行き来します。

| タブ | 内容 |
|---|---|
| ホーム | 看板カード、デイリーミッションの進み具合、お知らせ・ミッション・プレゼント、バナー、ワンタップでバトル開始。左上のランク・称号・名前からプロフィールへ |
| バトル | レート戦・フリー対戦・フレンド対戦・遊び方の4枚と「今日の初勝利」 |
| デッキ | デッキ一覧（キーカード・コスト分布・スリーブと文字盤とマット）と編集（3列のカード一覧、キーワード絞り込み、おすすめ、デッキ確認） |
| ショップ | パック（伝説の確定までのゲージ、引く前の確認、提供割合）、スリーブ、盤面の文字盤、プレイマット、テーマ一式、欠片で作る |
| その他 | プロフィール、カード図鑑、ミッション、プレゼント、お知らせ、ランキング、遊び方、攻略wiki、設定 |

UI の部品は `src/ui/kit.ts`、画面ごとのスタイルは `src/ui/skin.css`。

- **称号（`src/meta/titles.ts`）：** 20種。勝利数・対戦数・予約や召喚の回数・ログイン日数・パック開封・カード収集・レート戦の最高段位など、端末に既にある数字で解放されます。プロフィールで選んだものが名前の下・VS画面・ランキングに出ます。
- **プロフィール：** 名前・称号・ひとこと・看板カードの変更、戦績、よく使うデッキ（直近20戦と累計の割合）、直近30戦の戦歴。
- **VS画面：** 対戦の前に、両者の看板カード（自分はデッキのキーカード）・名前・段位・称号・先手後手を表示（タップで飛ばせます）。
- **攻撃の予告：** 攻撃できるユニットを選ぶと、ルールどおりの攻撃先へ矢印が伸び、相手の体力・反撃・貫通の結果を先に表示します（設定で消せます）。
- **着せ替え（`LOOKS`、`src/meta/economy.ts`）：** スリーブ（カードの裏の柄）・盤面の文字盤・プレイマット。それぞれ最初から持っている標準1種＋8テーマ。コインで交換し、デッキごとに選べます。以前売っていたもの（旧スリーブ4種・旧文字盤4種・緑の卓）は販売を終え、持っていた人には起動時に代金をコインで返します（`refundRetired`）。
  - **テーマ（`THEMES`）：** 透かし機械・天文時計・大聖堂・蒸気機関・和時計・深海の羅針盤・鍛冶場・記憶の書庫の8つ。文字盤400・スリーブ200・マット400コイン（`THEME_PRICES`）。3点セットは800コイン（`THEME_SET_PRICE`）で、一部を持っていればセット価格からその代金を引いた額（ただし単品の合計を超えない）でそろう（`themeOffer`/`buyTheme`）
  - **絵（`src/render/lookArt.ts`）：** SVGで描き、起動時（スリーブ）と対戦前（文字盤・マット）にキャンバスへ焼いて使う（`src/render/looks.ts`）。文字盤の目盛・数字・針・終焉の帯はゲームが描くので、どの文字盤でも読みやすさは同じ。歯車や黄道の輪は別の層で回り、炉の光や蝋燭は明滅し、火の粉・波紋・蒸気は `src/render/lookFx.ts`。設定の「動きを減らす」で止まる
  - **プレイマット：** 自分の側（区切り線から下）に敷く。背の高い画面では拡大して埋める。相手のマットは相手側に上下逆・半透明で出る
  - **オンライン：** スリーブとマットはプロフィールとして相手に渡る（サーバーは存在する見た目のIDだけを通す）。観戦では標準の見た目
- **振動：** 盛り上がる場面（伝説の登場・決着・大ダメージ）と操作の手応えを別々にオン／オフ（`src/render/haptics.ts`）。
- **結果画面：** 進んだデイリーミッション、ランクのEXP、コイン、デッキのキーカードを表示。

進行要素（`src/meta/progress.ts`、報酬はすべてゲーム内のコインとパックチケット）:

- ログインボーナス：7日周期（7日目はパックチケット）。プレゼントボックスに届く
- デイリーミッション：日替わりで3つ（対戦・勝利・召喚・予約・攻撃など）、全達成でボーナス
- 初心者ミッション：はじめての対戦、パック開封、デッキ保存、「つよい」AIに勝利など8つ
- プレイヤーランク：対戦でEXP（勝利100・敗北40、つよい×1.5、オンライン×1.2）。ランクアップごとに50コイン、5の倍数でチケット
- お知らせ：`NEWS` に追記すると未読バッジが付く。版番号は `src/version.ts`

## レート戦

レートを競い、友達ランキングで比べるモードです（`src/meta/rating.ts`、`src/server/leaderboard.ts`）。

**対戦相手はAIですが、画面上はプレイヤーとして見せます。** 相手は名簿の120人（`src/meta/roster.ts`、Lv1〜10に12人ずつ）で、名前ごとにLv・性格・得意デッキ・サブのデッキ・癖が決まっています。マッチング待ち（2〜6秒）、1手45秒の持ち時間、人間らしい考慮時間を付け、AIや強さの段階はどの画面にも表示しません。相手の表示レートは名簿のレートで、レート計算にもこの数字を使います。

- **相手の選び方：** 自分のレートに近い相手ほど出やすく（`rivalPool`）、直近5戦の相手は出ない。第2弾のデッキが得意な相手は、第2弾の配信まではサブのデッキを使う。前回その相手に勝っていると、30%でサブのデッキに持ち替えてくる。VS画面の看板カード（デッキで最もレアなカード）と称号は相手ごとに固定。
- **AIの頭脳（`src/core/rival.ts`）：** 1手ごとに ①候補を出す ②Lvの深さで点をつける ③とどめ・必ず守る・大差なら最善手 ④最善手との差が「互角の幅」以内の手だけを性格の重みで選び直す ⑤同点なら名前の癖（好きなレーン・予約の早さ・引くタイミング）で決める。強さを決めるのはLvだけで、性格・作戦・癖は同じくらい良い手のどれを選ぶかだけを変える。
- **Lv：** 読みの深さ（盤面だけ／相手の攻撃を1手先まで／試し打ち）、点数のブレ、互角の幅、7種のミス（攻撃の見落とし・脅威の見落とし・予約の時刻ずれ・出し惜しみ・置き間違い・とどめを逃す・守りを忘れる）の確率で決まる。とどめと守りのミスはLv4から0。
- **作戦（`src/core/plans.ts`）：** 20デッキそれぞれの使いどころ（例：秒針突撃の刻印の雷はとどめ用に取っておく、時間牢獄の停滞の檻は準備間近の相手へ）。Lv1〜2は基本の1つを半分、Lv3は基本の1つ、Lv4からすべてと共通ルール（相手の時計を鐘の向こうへ押し出すとその鐘のドローが消える、など）。
- **人間らしさ：** 考える時間は手の難しさで変わる（自明0.6〜1.2秒・迷う手2.5〜5.5秒・大事な手+1秒、連続行動の2手目から×0.6、序盤×0.75・終盤×1.25、名前のテンポ×0.8〜1.2、最長9秒）。迷った手では相手の手札が1枚持ち上がって戻る。試合ごとに調子（0.7〜1.3）がある。Lv4以上は勝ち目がなくなると降参することがある。
- **Lvの間隔（`npm run sim:rivals -- <LvA> <LvB> [試合数]`、AI同士・各Lvの名簿のデッキから抽選）：** 上のLvの勝率は Lv1→2 62%・2→3 63%・3→4 60%・4→5 59%・5→6 55%・6→7 48%（±5）・7→8 63%（±6、Lv8から環境デッキ）・9→10 50%（24試合）。Lv5より上は読みを深くしても強さがほとんど変わらないため、Lv6〜7とLv8〜10はほぼ同じ強さ（Lv8からはデッキの差で強い）。性格の差は同じLv・同じデッキで堅実型と比べて±3%以内（Lv3・4で確認）
- **Lv9：相手のデッキを推測する（`src/core/infer.ts`）：** 見えたカード（場のユニット・使われた術・公開された予約）から、名簿で使われる全デッキと基本デッキのどれかを確率で推測し、試し打ちでは相手の手札と山札をそのデッキの残りから仮に決める（見えたカードが3枚未満のうちは半分を全カードから）。推測の1位が60%を超えたら、デッキの作戦の「相手別」ルール（例：破約の刃を持つ相手には予約を2つ重ねない、速攻相手には全体除去を待つ）も使う。
- **Lv10：予約も先読みする：** 相手の公開されていない予約は、時刻（文字盤のピン）だけを残し、中身は推測したデッキのまだ見えていない術から仮に決める。自分の予約の時刻は「相手の次の行動の直後」「鐘の1刻前」「20刻」「相手の予約の1刻前」も候補に入れ、試し打ちの中でも予約を打つ。
- **伏せた予約はのぞかない：** 試し打ちは、相手の公開されていない予約の中身を使わない（超つよい・Lv5以上。以前は試し打ちの世界に中身が残っていた）。
- 仕様書：「対戦相手名簿」のページ（性格の重み・ミスの確率・20デッキの勝ち筋と設計図）。
- **環境の集計（`src/server/env.ts`）：** レート戦の記録に相手のid・Lv・デッキとその版・試合時点のレートを付けて送り、サーバーが日（日本時間）ごとに足し込む。①段位ごと×アーキタイプごとの試合数・人数・結果の合計・期待勝率の合計（デッキの強さは 結果 − 期待勝率 で見る）②名簿の相手のリストの版ごとの成績 ③プレイヤーが使った20枚の組み合わせの一覧（最大2,000種類、新しいデッキ・型の発見用）④フレンド対戦のアーキタイプどうしの相性。読み出しは `POST /api/env {days}`（公開・個人の情報なし）と `POST /api/env/lists {token}`（管理用）。
- **設計図（`src/meta/blueprints.ts`）：** 20アーキタイプの核・一覧の範囲・役割の範囲・戦い方の基準値と戦型の判定。プレイヤーのデッキは、最初の版と20枚中12枚以上共通する最も近いアーキタイプに振り分ける（どれとも12枚未満は未分類）。
- **AIのデッキ帳（`src/meta/deckbook.ts`）：** 名簿の相手のリストをサーバーから配る（`POST /api/decks`、書き込みは `POST /api/decks/publish {token, book}`）。ゲームは起動時に読み込み、設計図の確かめ（20枚・枚数の上限・ゲームにあるカード・核・最初の版から6枚以内・一覧と役割の範囲）に通ったリストだけを使う。通らないリストや読めないときは、ゲームに入っているリスト。お試しの版は、試合ごとに決まる割合の試合でだけ使う。デッキ帳はまだ空（毎日の改良の仕組みが書き込む）。
- **毎日の改良と発見（`src/sim/daily.ts`・`src/sim/evolve.ts`、GitHub Actions「Daily rival decks」が毎日4:30に実行）：** ①お試し中のリストを実戦で判定（300試合で今の版より5ポイント以上悪ければ取り下げ、そうでなければ採用、14日で300試合に届かなければシミュレーションの結果で採用）②その日の当番のリスト（既定4つ、毎日入れ替わる）を、同じ役割のカードで1〜2枚入れ替えた案（最大20）でシミュレーション。Lv8〜10用は勝率が2ポイント以上・95%の幅の下限が0より上の案、Lv1〜7用は強さが±2ポイント以内の新しい案だけを選び、さらに設計図の戦い方（戦型・終わる刻・KO勝ち・20刻までの拠点ダメージなど）を外れた案は捨てる。相手は、そのリストを使う名簿の相手の段位でプレイヤーが使っているデッキの比率（データが50試合未満なら全デッキ均等）③選んだ案は新しい版として、レート戦の半分の試合でお試し ④新しいデッキ（未分類のリストで15人・100試合・3日以上）と型（同じアーキタイプで最初の版から3枚以上違い、8人・50試合以上）の候補、バランス（段位で使用率30%以上かつ期待より5ポイント以上勝つ）を見つけたら Issue「確認が必要なこと（AIのデッキ）」に書く。新しいデッキと型は自動では名簿に入れない（設計図を確認してから手で足す）。実行結果は Actions の Summary とアーティファクトに残る。`SCALE=0.1 FAKE=… npm run daily` で手元でも試せる
- **デッキ帳は2種類：** Lv8〜10用（アーキタイプのid）とLv1〜7用（id に `~lo`）。版番号はデッキ帳全体で通し番号なので、記録の（デッキ, 版）で1つのリストが決まる
- 必要な設定：GitHub の Variables に `ONLINE_URL`（Pages と同じ）、Secrets に `ADMIN_TOKEN`（サーバーの `ADMIN_TOKEN` と同じ値）
- 初期レート1000。Elo方式で増減（K=24、はじめの10戦はK=40）。以前の9段階のAI（やさしい〜超つよい＋＋）のidも、記録済みの試合のために残している
- 降参・途中でアプリを閉じた場合は敗北（次回起動時に記録）
- ランキング：サーバーは端末ごとの匿名IDで記録し、**レートの数値ではなく試合結果を受け取って同じルールで計算し直す**。同じ試合の二重送信、1分未満の勝利、1分以内の連続した勝利、未来の日時は受け付けない（敗北は常に受け付ける）。通信できないときは端末に貯めて後で送る
- ランキングはこのサーバーで遊ぶ全員が対象です（友達だけで使う前提）。不特定多数に公開する場合はグループ分けが必要です

## 第1弾「残響の刻」

新カード30種（通常12・希少10・秘宝5・伝説3）と4つのキーワード＋「予約専用」。

| キーワード | 効果 |
|---|---|
| 残響N | 効果が解決してからN刻後に、弱い効果がもう一度起きる。時計に丸いピンで公開表示。予約の枠は使わず、同時に3つまで |
| 共鳴 | 自分の予約か残響が発動するたびに効果が起きる |
| 急襲N | 自分の時計が相手より2刻以上遅れているとき、コストがN少なくなる（最低1） |
| 充填N | 今すぐ使うとき、最大N刻まで多く払って効果を強める（予約するときはX＝0） |

### 追加カード（0.18.0、同じ「残響の刻」パックに収録）

| カード | 種別 | コスト | 効果 |
|---|---|---|---|
| 城崩しの槌兵 | 通常・ユニット | 3 | 挑発を持つユニットを攻撃するとき攻撃+3 |
| 時計塔の衛士 | 通常・ユニット | 3 | 挑発。相手の予約か残響が発動するたび攻撃+1（最大+5） |
| 送り返しの風 | 通常・呪文 | 3 | 攻撃力が最も高い敵ユニットを手札に戻す。予約時はさらに1枚引く |
| 忘却の砂 | 希少・呪文 | 2 | 相手は手札を1枚選んで捨てる。カードを1枚引く。予約時はさらに1枚引く |
| 星読みの占者 | 希少・ユニット | 2 | 登場時：山札の上3枚から1枚を選んで手札に加える |
| 囮の書 | 希少・呪文 | 2 | **予約専用**。相手に破棄されたら相手の時計を4進める。発動したらカードを1枚引く |
| 時の簒奪者 | 秘宝・ユニット | 5 | 登場時：相手の最も早い予約か残響を奪う（1刻早く発動） |
| 記憶の司書ミレア | 伝説・ユニット | 5 | 登場時：使った呪文（伝説以外）を1枚、コストなしでもう一度使う |

- **予約専用**：手札から直接は使えず、時計の好きな刻（予約できる範囲内）に重ねて予約するカード。予約の枠（2つまで）を使います
- 選ぶ効果（星読み・忘却の砂・ミレア）は対戦画面に選択パネルが出ます。オンラインでは相手に選択肢や引いたカードは見えません
- オンライン対戦は通信の版（`NET.PROTOCOL`）をそろえないと入れません。古いアプリには再読み込みを案内します。**Pagesとオンラインサーバーは同時に更新してください**
- 配信記念として、2026-11-30までにログインした人へパックチケット3枚をプレゼント（`GIFTS`、`src/meta/progress.ts`）
- 一度獲得した称号は、条件から外れても失われません

設計方針は「基本カードに選択肢を足すが、置き換えない」。例えば「時計塔の守衛」は「砂時計の番人」の上位互換にせず、4コストの挑発として別の枠に置いています。

### バランス検証（基本4デッキ＋パック入り4デッキ、AI同士9,600戦）

| 指標 | 結果 |
|---|---|
| 先手 / 後手 | 48.1% / 51.7% |
| パック入りデッキの対基本デッキ平均勝率 | 残響 50% ・ 急襲 49% ・ 均衡+ 52% ・ 城塞+ 53% |

### コインとパック（`src/meta/economy.ts`）

- 報酬：AI（ふつう）勝利25・（つよい）勝利35・オンライン勝利30、敗北10〜12、引き分け15〜18。**対戦の報酬は1日250コインまで**。その日の初勝利+50。自分の行動が5回未満の対戦と降参はコインなし
- 最初にパックチケット3枚を配布
- 1パック100コイン・5枚：通常3・希少1・最後の1枚は希少72%／秘宝23%／伝説5%。伝説が出ないまま15パック目で確定（天井）。伝説は未所持のものを優先
- 上限枚数（2枚、伝説1枚）を超えたカードは**欠片**に（通常5・希少20・秘宝100・伝説400）。欠片で好きなカードを作成（通常40・希少100・秘宝400・伝説1600）
- 重複がコインで戻る仕組みは、カードが揃うとパックが自分の代金を払ってしまう（開け放題になる）ため廃止しました。すべて揃った状態で開けても、1パックあたりの欠片は約110です
- 提供割合はショップ画面で公開しています
- 所持カードとコインは端末（localStorage）に保存しています。**オンライン対戦のサーバーは所持を検証していません**。ランキングなどを入れる前にアカウントとサーバー側の所持管理が必要です

コンプリートまでの目安（ログインボーナス・ミッション・ランク報酬・欠片での作成を含む、各60人分の平均）:

| 1日の対戦数 | コンプリート | 伝説2種がそろう |
|---|---|---|
| 2 | 約10日 | 約7日目 |
| 5 | 約7日 | 約4日目 |
| 10 | 約5日 | 約3日目 |

第1弾は収録が30種と少ないため、1〜2週間で揃う設定にしています。第2弾以降は1弾40〜60種を想定しており、同じ報酬のままでも揃うまでの期間はおよそ2〜3倍に延びます。

  meta/      コイン・報酬・パック抽選

## 攻略wiki

`wiki/index.html` を入口にした2ページ目で、ゲームと一緒にビルドされて `/wiki/` に公開されます（GitHub Pages なら `https://<ユーザー名>.github.io/chrono-duel/wiki/`）。ゲーム内では「メニュー → 攻略wiki」と「遊び方」の一番下から開きます。開発中は `npm run dev` のあと `http://localhost:5173/wiki/`。

- カードの数値・効果文、デッキ、ルールの数値、パックの確率と報酬は `core/` と `meta/` を直接読んで表示します。カードを追加・調整すると、次のビルドでwikiも変わります。
- 採用時勝率・使用回数・相性表は `src/wiki/stats.ts`（生成ファイル）から表示します。カードやバランスを変えたら `npm run wiki:stats` で作り直してコミットしてください（6,400戦で1分ほど）。
- 攻略メモ・デッキ解説・用語集などの文章は `src/wiki/content.ts` に書きます。新カードは `MEMO` に1行足すと「攻略」欄が出ます（無くても表示されます）。
- 各ページは `#cards` `#decks` のようなURLで直接開けます。

## オンライン対戦

サーバーが正しい状態を1つだけ持ち（`src/server/room.ts`）、各プレイヤーには「見てよい部分だけ」を送ります。相手の手札・山札の並び・公開されていない予約の中身は、通信にも載りません（`src/core/net.ts` の `viewState` / `viewEvent`）。クライアントは行動の希望を送り、サーバーがエンジンの合法手と照合して結果を返します。

- **1手45秒：** 過ぎると自動で「待機」。3回続けて過ぎると投了扱いです（前の演出ぶんの猶予つき）。
- **切断：** 60秒以内に戻れば続きから再開できます（ページを再読み込みしても、端末に保存した席で復帰）。その間は時計が止まります。
- **再戦：** 双方が押すと、先手・後手を入れ替えて始まります。
- **観戦：** あいことばで部屋に入り、両者の手札を伏せたまま対戦を見られます（1部屋8人まで）。山札や予約の中身は観戦者にも送りません（`watchState` / `watchEvent`）。
- **部屋の中での変更：** 対戦が始まる前なら、部屋の中でデッキと名前を変えられます（`setup` メッセージ）。

### 公開する（Cloudflare Workers）

1. Cloudflare のアカウントを作り、**API トークン**（テンプレート「Edit Cloudflare Workers」）を作る。
2. GitHub のリポジトリで **Settings → Secrets and variables → Actions → Secrets** に `CLOUDFLARE_API_TOKEN` を登録（Cloudflare のアカウントが複数あるときは `CLOUDFLARE_ACCOUNT_ID` も）。Workers を初めて使うアカウントでは、先にダッシュボードの **Workers & Pages** を一度開いて workers.dev のサブドメインを決めておきます。
3. **Actions → Deploy online server → Run workflow**。成功すると `https://chrono-duel-online.<あなたのサブドメイン>.workers.dev` が使えます。（手元から出す場合は `cd server && npm install && npx wrangler login && npx wrangler deploy`）
4. 同じ画面の **Variables** に `ONLINE_URL` を登録。値は `wss://chrono-duel-online.<あなたのサブドメイン>.workers.dev`。
5. **Actions → Deploy to GitHub Pages → Run workflow** でクライアントを作り直す。

`server/wrangler.toml` の `ALLOWED_ORIGINS` に、遊ばせるサイトの Origin だけを入れています（独自ドメインで公開するときは追記）。料金や無料枠は Cloudflare の最新の案内を確認してください。

## 公開（GitHub Pages）

`main` へのプッシュで `.github/workflows/deploy.yml` がビルドし、GitHub Pages に公開します。初回だけ、リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にしてください。

## バランス調整の道具

- **`npm run balance`**：カードの強さを数字で測ります。均衡・秒針突撃・城塞・残響の4デッキに入っている「振り子兵」（能力なしの2コスト 2/3）2枚をそのカードに入れ替え（伝説は1枚）、AI「つよい」でテスト用の8デッキと対戦させて、勝率がどれだけ変わったかを「価値」として出します。±3は誤差、+7以上は強すぎ、−6以下は弱すぎの目安です。`--games 80` で対戦数を増やすと誤差が小さくなります。カードの数値を書き換えてからもう一度回せば、調整案をそのまま試せます。
- **実戦データ**：遊ぶたびに、自分側のデッキ・使ったカード・勝敗が匿名でランキングと同じサーバーに送られ、バージョンごとにカード別の成績が集計されます。攻略wikiの「実戦データ」タブか `npm run stats:real -- <サーバーのURL>` で見られます。「影響」は使った試合の勝率から同じ対戦モードでの平均勝率を引いた値で、AIの強さの違いを差し引いたカードの効き目の目安です。
- **対戦の記録**（0.12.2〜）：1試合ごとに、シード・両者のデッキ・全行動を保存します。エンジンは決定的なので、これだけで試合を最初から最後まで再現できます（`src/core/gamelog.ts` の `replay`）。AI戦は報告に記録を付けて送り、サーバーが再生して結果が合うものだけ保存します。オンライン対戦は部屋が記録して渡します。1試合あたり1〜6KB程度です。記録は管理用トークンがないと読めません。
  - サーバー側：GitHubのリポジトリ設定（Settings → Secrets and variables → Actions）に `ADMIN_TOKEN` という名前で好きな長い文字列を登録し、Actions の「Deploy online server」を実行すると、サーバーに設定されます（`cd server && npx wrangler secret put ADMIN_TOKEN` でも可）。未設定なら記録は保存されるが読み出せない。
  - 取得と分析：`npm run logs -- https://<サーバー> <トークン> [バージョン]` で全記録を `logs/<バージョン>.jsonl` に保存し、モード別・攻撃回数別・デッキ別・プレイヤー別に、勝率・攻撃回数・拠点ダメージのうちユニットによる割合・時間切れ決着の割合を表示します。`--player <名前>` でその人の試合とデッキを1試合ずつ、`--csv out.csv` で席ごとの表を出せます。保存したファイルは `--file logs/<バージョン>.jsonl` で読み直せます。`--game <試合ID>` で1試合を1手ずつ表示します。
  - スマホから：攻略wikiの `…/wiki/#admin`（メニューには出ない）でトークンを入れると、試合の一覧（名前で絞り込み）と1手ずつの経過が見られます。「経過をコピー」「記録（JSON）をコピー」で、そのまま貼り付けて共有できます。ランキングに参加している人は、ランキングの名前で表示されます。
